# 数据目录与卸载语义（重要）

应用只管理自己的**标准数据根**：`/vol1/@appdata/mail-archiver-fnos/data`。
数据默认来自系统分配的**共享目录**（`config/resource` 声明的 `data-share`，`/vol1/@appshare/<app>/data`），安装时由 fnOS 自动创建并授权。

如果你在安装向导里指定了别的目录（例如 `/vol2/1000/MailArchive`），标准数据根会成为一个**符号链接**：链接由应用管理，**目标目录由你管理**。

## 卸载时各是什么下场

| 数据根形态 | 「保留数据」 | 「删除数据」 |
|---|---|---|
| **真实目录**（`@appdata/.../data`） | 保留整目录，重装沿用旧账号 | 删除应用自有目录；重装得到全新空库 |
| **符号链接**（指向你的存储空间目录） | 保留链接与目标，重装沿用旧账号 | **只删符号链接本身**；你目录里的数据一个字节都不会动（日志会打印「保持不动」+ 绝对路径） |
| **共享目录 `data-share`** | 保留 | ⚠ **平台会连同该共享目录一起删除**（实测 `MAINEVENT DeleteFile`），安装脚本无法拦截 |

> ⚠ **卸载前务必先备份**：`pg_dump` 导出，或把整个数据目录复制到你自己的位置。默认数据就在共享目录里，一旦「删除数据」，平台会把共享目录一起清掉。

## 换数据目录会发生什么

**当前版本不支持运行期热切换**（Docker 需要在容器启动时 bind 挂载）：

1. 想要换位置 → **卸载（保留数据）→ 重装时在向导里指定新目录**
2. **新目录是空库**（0 账号、0 邮件）——应用只会使用新目录里的数据
3. 原数据**完整保留**在原处，**没有被删除**；如需沿用，先把原数据迁到新目录再启动

> 一句话：**「删除数据」删的永远是应用自己的东西（共享目录除外，平台会一起删）；你自己目录里的数据只能你自己删。**
