# 安装说明（Mail-archiver for fnOS）

> 适用于 v0.1.16 及之后版本。安装包从 [Releases](https://github.com/a10463981/mail-archiver-fnos/releases) 下载。

## 一、前置条件

- fnOS 系统版本 **≥ 1.2.0401**，架构 **x86_64**，内存建议 **≥ 4GB**
- 安装包**内嵌应用镜像**（离线 `docker load`）；唯一需要联网的环节是拉取数据库镜像 `postgres:16-alpine`

## 二、安装步骤

1. 应用中心 → **手动安装** → 选择下载好的 `mail-archiver-fnos-<版本>.fpk`
2. 向导填写：管理员用户名、**管理员密码（仅首次建库生效）**、时区（如 `Asia/Shanghai`）
3. 完成 → **启动** → 从**桌面**打开「邮件归档」

首次登录会停在「修改密码」页，属上游对初始密码的保护，改一次即可。

## 三、口令与日志

- 安装日志里的管理员口令是**掩码**（如 `Ma****6!`），**完整明文只在 `@appconf/mail-archiver-fnos/admin_password`（600）**
- **勿截图或外传安装日志**；`@appconf` 下文件均按敏感件对待
- 应用运行日志：`docker logs --tail 200 mail-archiver-fnos`（**不是** `@appdata/.../logs`，该目录未使用）

密码语义与忘记密码的三条自救路径见 [`PASSWORDS.md`](PASSWORDS.md)。

## 四、数据目录

- 默认放在系统分配的**共享目录**（`config/resource` 声明的 `data-share`），安装时自动创建并授权，**不需要**手工授权或 `chown`
- 想放到数据盘（如 vol2），在**安装向导**里指定；**运行期不支持热切换**（刻意设计，避免服务中断与搬数据风险）
- **改数据目录不会搬运已有数据**：新位置是空库，旧数据留在原处，详见 [`DATA-DIRECTION.md`](DATA-DIRECTION.md)

## 五、0.1.16 修复的 6 条（历史版本要点，均已被后续版本继承）

这 6 条都属于「会让你误以为数据没了 / 密码不对」的类型：

| # | 修了什么 |
|---|---|
| MF-1 | 改数据目录后**自动重启**并明确提示「新目录是空库、原数据完整保留在 `.bak-<时间戳>`」，避免点完启动看到空库而误判丢数据 |
| MF-2 | 安装日志**只对「新建库」打印密码**；沿用已有数据时改为「向导密码不生效，请用原密码」 |
| MF-3 | 打印的是**掩码**，完整口令只落 `@appconf/admin_password`（600），安装日志不含明文 |
| MF-4 | 设置页重置密码**只调用一次** CLI（旧版两次导致双写库、双审计） |
| MF-5 | 数据清理白名单在 `TRIM_PKGVAR` 为空时**直接拒绝**，并改为精确匹配 `${TRIM_PKGVAR}/data` |
| MF-6 | `data-purge.sh` 缺失时**安装中止**并提示打包不完整（旧版会静默跳过「已有数据库检测」） |

> 注：0.1.22 起**移除了运行期切换数据目录**（方案 B），改为只在安装/重装时决定数据位置；MF-1 的提示逻辑保留在重装路径里。

## 六、安装时提示「存在安装历史」

平台在安装前会检查本应用残留。新版 `install_init` 会清理平台临时目录中的本应用残留并在日志写清清了什么；若平台在更早一步就拦住（脚本还没跑到），请手工删除下面两个路径后重装：

- `/vol1/@apptemp/mail-archiver-fnos`
- `/var/apps/mail-archiver-fnos`（若已不存在则忽略）

**只删这两个，别删别的。**

## 七、卸载

两种选项的差别见 [`UPGRADE-UNINSTALL.md`](UPGRADE-UNINSTALL.md)；一句话：**「删除数据」只删应用自有目录，共享目录与你自己的存储空间目录都不会被动。**
