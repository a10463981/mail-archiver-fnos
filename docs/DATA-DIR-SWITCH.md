# 为什么不支持"运行期切换数据目录"（0.1.22 起）

0.1.22 起，应用设置里的「数据目录」是**只读展示**；运行期不再执行任何迁移。

## 原因
一次运行期切换要同时满足 4 件事，任一不满足就表现为"应用起不来/白屏/保存一直转圈"：

1. 数据根符号链接改向；
2. **两个容器都要 `--force-recreate`**（bind mount 的符号链接只在容器创建时解析）；
3. 目标库的 `mailarchiver` 角色口令必须**先对齐**，否则应用 28P01 起不来；而"等应用起来再自愈"是死锁；
4. 载荷 `${TRIM_APPDEST}/docker/` 的 `app.env`/`pg_password`/`docker-compose.yaml` 必须齐全。

而且平台在"保存配置"时会先 STOP 应用、再自己 START，与我们脚本的 `compose down/up` 天然抢跑（历史事件 `APP_START_FAILED_DOCKER_COMPOSE_EXCEPTION`）。

## 正确的换目录方式
1. 应用中心 → 卸载 → 选 **保留数据**
2. 手动安装 `.fpk` → 向导里指定新目录
3. 启动 → 用原密码登录（若新目录是全新空库，会要求建号/首登改密，属正常）

## 仍保留的自愈能力
- 每次启动前自动补齐载荷 `docker/` 三件套（`ensure_payload_docker_dir`）
- 安装/升级路径的数据目录选择与迁移逻辑不变
