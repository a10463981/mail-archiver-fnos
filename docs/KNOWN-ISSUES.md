# 已知问题与边界（截至 26.10.01）

本清单如实列出**尚未验证**、**设计取舍**与**平台限制**三类事项；不含性能数字与用户数据。

## 一、仍待确认

| 项 | 说明 |
|---|---|
| 免密登录的真机覆盖 | 「登录 fnOS 后从桌面打开应用免二次登录」依赖 fnOS 网关注入的身份头。相关缺陷本版已修，但**是否在所有真机/所有系统版本上生效仍在用户侧确认中**。若出现被要求重新登录，请附 `docker logs` 与浏览器 URL 提 issue。 |
| 镜像构建路径 | 受构建期网络限制（`mcr.microsoft.com/dotnet/sdk:10.0` 不可达），镜像改用**等效路径**构建：用 .NET SDK 10.0.100 tarball 发布源码 + 复用 `aspnet:10.0` 并逐条复刻上游 Dockerfile 最终阶段。**产物内容等价（可执行文件/权限/目录/入口一致），镜像层结构不同（少 SDK 层）**。详见 Release 26.10.01 说明。 |
| 换用户不串号（跨用户隔离） | 未验证。 |

## 二、设计取舍（不是 bug）

| 项 | 说明 |
|---|---|
| 运行期不支持切换数据目录 | 本版不提供热切换：换位置 = 卸载（保留数据）→ 重装时指定。避免服务中断与「搬一半数据」的风险。 |
| 改数据目录不搬运数据 | 新位置是空库；旧数据留在原处（`.bak-<时间戳>` 或符号链接目标）。详见 `DATA-DIRECTION.md`。 |
| 首次登录强制改密 | 上游对初始密码的保护行为。 |
| 密码只存哈希 | 无法查看，只能重置：应用设置 → 运行设置 → 管理员登录密码，或 CLI `--reset-password`。 |
| 共享目录（data-share）的卸载归属 | 安装脚本不会删共享目录；但**平台在「删除数据」时会把 `data-share` 一并删除**，「保留数据」对 share 目录也不保证成立。因此**卸载前请先备份**（`pg_dump` 或整目录复制）。 |
| 应用内「日志」页 ≠ 运行日志 | 该页是访问审计（`AccessLogs` 表）；运行日志只能 `docker logs mail-archiver-fnos`。 |

## 三、平台 / 上游限制

| 项 | 说明 |
|---|---|
| 平台不允许命令行覆盖已装应用 | 升级必须走「卸载（保留数据）→ 手动安装」。 |
| 安装前残留检查 | 若平台在脚本执行前就拦住，需手工删除 `/vol1/@apptemp/mail-archiver-fnos` 与 `/var/apps/mail-archiver-fnos`。 |
| fnOS 内部 API 不可用时改用官方 data-share 范式 | `trim.file.checkUserACL` 等接口在测试环境返回 `200006 Internal Error`，故当前版本改用 `data-share` 声明，由系统自动建目录并授权。 |
| 数据库大版本固定 | `postgres:16-alpine`；跨大版本必须 dump/restore。 |

## 四、常见误判（看起来像丢数据/密码错）

| 现象 | 真相 |
|---|---|
| 改目录后打开是空库 | 新目录本来就是空库；旧数据完整保留在原处 |
| 重装后向导密码登不上 | 保留数据重装时向导密码不生效，用原密码 |
| 「删除数据」后自己的目录还在 | 设计如此：只删应用自有目录/符号链接，不动用户目录 |
| 找不到应用日志文件 | 应用只写 stdout，日志在 `docker logs`，`data/logs` 未使用 |
| 备份后换机恢复失败 | 备份必须含整个 `data/pgdata`（或使用 `pg_dump`），且备份文件含凭据痕迹，按敏感件保管 |
