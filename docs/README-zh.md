## 📁 数据目录怎么选才会成功

### 先讲清一个"鸡生蛋"问题
**首次安装时，应用还不存在**，所以**无法**在「应用设置 → 访问权限」里给目录授权。
因此：

> **只有两类目录能在安装向导里直接用得起来**：
> ① **默认目录**（应用自有，安装时自动创建、属主自动正确）；
> ② **已经可写**的目录（属主为应用运行用户 `987:982`，或已授权且 ACL 真的生效）。

### 想用自己存储空间里的目录？三步走
```
1) 先用【默认目录】安装一次（向导里数据目录选「默认」）
2) 装好后：应用设置 → 访问权限 → 把目标目录授权给本应用
3) 应用中心 → 卸载 → 选【保留数据】→ 重新安装 → 向导里指定该目录
```

### 技术替代（不想走三步时，root 执行其一）
```bash
# A. 改属主（推荐，最稳）
sudo chown -R 987:982 /vol1/1000/你的目录 && sudo chmod 755 /vol1/1000/你的目录

# B. ACL 授权（注意：部分存储卷 ACL 不被强制生效，优先用 A）
sudo setfacl -R -m u:987:rwx -m d:u:987:rwx /vol1/1000/你的目录
```

### 常见错误对照
| 现象/报错 | 含义 | 处理 |
|---|---|---|
| `数据目录不可写：<路径>` | 运行用户 `987` 写不进去（未授权/属主不对/权限 0） | 三步走，或 `chown -R 987:982 <路径> && chmod 755 <路径>` |
| `目录 … 属主为 UID xxxx，不是 987` | 属主不是应用用户 | 同上 A |
| `Permission denied`（容器内 `/run/secrets/pg_password`） | 载荷口令文件属主不对 | 0.1.22+ 每次启动会自动补齐并修正；手动：`chown 987:982 /var/apps/mail-archiver-fnos/docker/pg_password && chmod 600` |
| `28P01 password authentication failed` | 目标库口令与当前配置不一致 | 0.1.21+ 安装/切换时会自动 `ALTER ROLE` 对齐 |

### ⚠️ 运行期不支持切换数据目录（0.1.22 起）
应用设置里的「数据目录」是**只读展示**。换目录请走上面的**卸载（保留数据）→ 重装时指定**。原因见 `docs/DATA-DIR-SWITCH.md`。

## 🗑️ 卸载与数据：删除 / 保留 × 四样东西

| 卸载选项 | 应用自有默认目录<br>`@appdata/<app>/data` | 你授权的个人目录<br>`/vol1/1000/xxx` | 目录记忆<br>`@appconf/<app>/data_target` | 访问权限授权<br>(ACL / 平台记录) |
|---|---|---|---|---|
| **删除数据** | **删**（真实目录删除；符号链接只删链接） | **不删**，一字节不动 | **清空** | **一并移除**（授权记录按应用 ID 存于 `appcenter.app_authorization_path`，应用删除即失效） |
| **保留数据** | **保留**（含 pgdata / mail） | **保留**，不动 | **保留**（重装时按它接回原目录） | **同样移除**（同上，授权是应用级记录） |

> **访问授权为什么在两种卸载里都会失效**：fnOS 的「访问权限」记录以 `app_id` 为键（`appcenter.app_authorization_path` 表，`app_id` 非空），应用被卸载即随之消失；重装是新 `app_id`，旧授权不会被继承。
> **但**：如果目录**属主已经改成应用运行用户 `987:982`**（`chown`），那"可写"来自文件系统属主/权限，**与授权记录无关，卸载重装后仍然可写** —— 这种情况下"装完直接指定目录"依然成立。

### 因此两条可行路径
- **想省事（不重新授权）**：先把目录 `chown -R 987:982 /vol1/1000/xxx && chmod 755`，之后卸载（删除或保留）→ 重装时可直接指定。
- **只用平台授权**：删除数据/保留数据卸载后，**重装完必须到「应用设置 → 访问权限」重新授权一次**，再指定目录。

### 推荐 SOP（首次使用个人目录）
```
1) 用【默认目录】装一次
2) 应用设置 → 访问权限 → 授权 /vol1/1000/xxx
3) 卸载 → 选【保留数据】
4) 重装 → 向导里指定 /vol1/1000/xxx → 启动
   （若第 4 步报"不可写"，说明授权记录没继承，先 chown 或重装后重新授权再指定）
```

## 📦 多磁盘怎么放（SSD 系统盘 + HDD 数据盘）

系统盘（通常 vol1/SSD）放应用与数据库默认目录；若你有独立 HDD 数据卷（如 vol2），建议把**数据目录**指到它：

1. 卸载（**选「保留数据」**）；
2. 重装时在「数据目录（可选）」填 `/vol2/1000/<你的目录>`；
3. 目录需对应用可写：`chown -R 987:982 <目录>`（或平台「访问权限」里授权应用）；
4. 注意：本卷的 ACL/权限模型可能与系统卷不同，若授权不生效，改用 `chown -R 987:982`。

**运行期不支持一键切换**：改数据目录必须卸载重装，原因是 Docker 需要在容器启动时就把该目录 bind 挂载进去，运行中无法热增挂载。

（0.1.40：沿用旧库时数据库口令会经 trust 通道自动对齐，装完即可用，不再 28P01。）

## 🔑 忘记密码 / 登录不上怎么办

**按顺序试，第 1 条是首选（最安全、立即生效）：**

1. **应用中心 →「邮件归档」→ 应用设置 → 运行设置 → 管理员登录密码** → 填新密码 → 保存。
   保存后**立即生效**（旧密码当场失效），应用内账号（默认 `admin`）即可用新密码登录。
   > 密码只以哈希形式保存，**无法查看**，只能重置。

2. **应用界面进不去、但容器还在跑**时，可用包内 CLI 直接重置：
   ```bash
   docker exec -e MFA_RESET_PASSWORD='你的新密码' mail-archiver-fnos \
     dotnet MailArchiver.dll --reset-password admin
   ```
   账号名以 `app.env` 里的 `Authentication__Username` 为准（通常就是 `admin`）。

3. **网关绑定异常导致始终进不去**时，先解绑再用密码登录，成功后可重新绑定：
   ```bash
   docker exec mail-archiver-fnos dotnet MailArchiver.dll --unbind admin
   ```

4. **两个口令不是一回事，别混**：
   - **管理员登录密码** = 网页/桌面登录用（第 1 条重置的就是它）；
   - **数据库口令** = 应用连 PostgreSQL 内部用，与登录无关。
     查看数据库口令明文用 `--show-db-password`（它**不是**登录密码）；只看指纹用 `--show-db-fingerprint`。

> 小提示：忘记密码不会导致数据丢失——账号与邮件都在库里，重置密码只是换掉登录凭据。
